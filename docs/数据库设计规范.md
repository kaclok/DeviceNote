# 数据库设计规范

> 2026-10-29 起生效，所有新建表与改表操作必须遵守（用户钦定铁律）。

## 铁律：状态类、类型类字段一律用数值类型，禁止 varchar

凡语义为「状态 / 类型 / 分类 / 档位 / 级别」的枚举列（`status`、`type`、`category`、`level`、`scope`、`state` 等）：

1. **类型用 `smallint`（int2）或 `int`**，不用 `varchar`。
   - 数值可比较、可排序、可走索引区间；省空间；
   - 从源头防脏值（varchar 会出现「正常」「normal」「1」并存）；
   - 值从 `0` 或 `1` 开始连续编号，`0` 常作「未知 / 默认 / 全部」。
2. **必须写列注释**，注释里列全枚举值含义，格式统一为 `值=含义` 顿号/空格分隔，例如：
   `0=跟随系统 1=始终横屏 2=始终竖屏`。
   - PG：`comment on column 表.列 is '...'`；MySQL：列定义内联 `comment '...'`。
3. **代码侧对应常量/枚举**，不散落魔法数字（如 `DataScope`、`ORIENT_FOLLOW` 的做法）。

## 正反例

- ✅ 正例：`nav.page_display.orientation int2`（`0=跟随 1=横屏 2=竖屏`，带列注释）。
- ❌ 反例（历史遗留，勿模仿、勿扩展）：`gb_record.gb_log.type varchar`（`M`/`A`）、
  `gb_record.gb_combine.abnormal_type varchar`、`dept_user.t_role.data_scope varchar`（`'1'~'4'`）。

## 存量表处理

- 历史表**不强制回改**（回改需迁移脚本 + 影响面评估，由用户确认后再动）；
- **新建表一律照此执行**；存量表加状态/类型列时也按数值类型执行。
