## 响应签名（今日新增）

需求: 前端给后端 params 会附加 __sign__/__timestamp__/__nonce__ 供后端校验(SignInterceptor, /cghtz/**)，现要求后端对返回 Result 的 data 也做 HMAC-SHA256 签名，前端校验；带全局开关。

实现:
- 后端:
  - Msg.java 增加顶层字段 sign(默认 null, jackson NON_EMPTY 时不输出, 对旧接口零影响)
  - 新增 logic/configurer/ResponseSignAdvice.java(@RestControllerAdvice): 开关 sign.response-enabled=true 且返回 Result+JSON 转换器、code=200、data 非空、无 @SignIgnore 时, 将 data 先序列化再解析成 JsonNode(与 HTTP body 输出完全同构), 递归生成"规范文本"(对象键按 UTF-16 字典序升序 {k:v,...}、数组 [..]、字符串原样不转义、布尔 true/false、null、数字整值十进制/浮点 stripTrailingZeros), SignUtil.sign() 得 HMAC 写 result.sign
  - application.yml 顶层新增 sign.response-enabled: false
- 前端(ft-checnote):
  - SignParamUtil.js 新增 canonicalJson(data)/signData(data) 与后端 canonical 算法严格一致; numberText 整数化, 字符串原样
  - Config.js 新增 verify_response_sign: false(与后端开关同步)
  - AxiosInst.js 响应拦截器: code==__OK__ 且 data 非空时若开启开关, 重算 HMAC 比对 body.sign, 不等或缺失则 reject(Error code=RESPONSE_SIGN_ERROR)

关键一致性约束(前后端 canonical 相同): 数字须在 JS 安全整数(±2^53)且非极小(≥1e-6)/极大(<1e21)范围; 对象键排序 Java String.compareTo(UTF-16 char) == JS Object.keys().sort()(UTF-16 code unit); data 序列化与解析共用同一 ObjectMapper 保证与 HTTP 输出同构(注意 NON_EMPTY 会过滤空集合/空字符串字段, 两侧都基于序列化后结果, 天然一致)。

## 请求验签全局开关（今日新增）

需求: 前端给后端 params 附加 __sign__/__timestamp__/__nonce__ 的机制(AxiosInst 请求拦截器 addSign + 后端 SignInterceptor 验签 /cghtz/**)也加全局开关，默认保持开启。

实现(默认 true=维持现状, 需两端同步关闭):
- 后端 application.yml sign 节扩展: request-enabled: true / response-enabled: false
- 后端 SignInterceptor: @Value("${sign.request-enabled:true}") requestSignEnabled, preHandle 开头 !requestSignEnabled 直接放行
- 前端 Config.js: request_sign_enabled: true
- 前端 AxiosInst.js 请求拦截器: 关键坑——原形参名也叫 config, 遮蔽了 import 的全局 config 对象导致读不到开关, 已把形参改名 reqConfig 并全文替换; if (config.request_sign_enabled) 才 addSign, 否则 params 原样透传
- 关闭注意事项: 前端关闭而后端仍开, 带业务参数无签名的请求会被拒 RC10401

## 前端响应签名豁免(等效后端 @SignIgnore)

需求: 后端 @SignIgnore 豁免的接口, 前端开 verify_response_sign 校验时会误报失败; 前端要有"等效注解"跳过。
结论: JS 无注解语法, 用等效机制(用户要求只保留方法级, 类级不处理):
- AxiosInst.js 新增 isResponseSignIgnored(response): 仅判断 response.config.__signIgnore__ === true
- 发起请求时传 option {__signIgnore__: true} (axios option 透传) 即跳过该校验
- 响应校验分支条件加 !isResponseSignIgnored(success); Config.js 无新增字段
- 简化: SignParamUtil.numberText 原两分支 return 相同(String(n))纯冗余, 已删成一行的 String(n), 行为零变化; 与后端 Java 数字处理一致矩阵不变(整数/浮点整值归一/stripTrailingZeros 各场景核对过)。
