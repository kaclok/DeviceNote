# 2026-09-09 工作日志

## fileview 项目: PDF 预览链路排查与「直链优先 + Blob 降级」方案

### 项目背景
- fileview = ft-checnote 内 `pages/smlj/fileview` + 后端独立 `CFileViewer(/x/fileview)`。
- 预览设计: 后端签发 MinIO 预签名 GET 直链(`/x/fileview/url/{id}`),前端拿直链让 Open File Viewer 直接访问 MinIO。不用后端代理字节流。
- 前端依赖: @open-file-viewer/core+vue 0.1.44(`OpenFileViewer` 具名导出;props: file/fileName/plugins/toolbar/theme/width/height/onError/onUnsupported)、pdfjs-dist v6、`pdfPlugin({workerSrc})`,样式在 `@open-file-viewer/core/style.css`。

### 关键实测结论(全部对真实 MinIO 10.8.54.24:9000 / minioadmin / 桶 store 验证)
1. 上传对象一律存成 `application/octet-stream`;若响应不覆盖 Content-Type,浏览器直接打开就是下载框。→ 预览直链必须 `response-content-type` 覆盖为真实 MIME。
2. 还要覆盖 `response-content-disposition=inline`(不带 filename,纯 ASCII,规避 RFC5987 中文编码)。
3. MinIO 侧 CORS 全绿: OPTIONS 对任意 Origin 回 204+ACAO;带 Origin 的 GET/Range GET 都回 ACAO(200/206)。curl 验证通过。
4. **但真实浏览器(Edge) fetch 直链仍被拦: "No 'Access-Control-Allow-Origin' header"** —— 本环境浏览器网络路径(代理 127.0.0.1:14397)会丢 Origin/ACAO,与代码无关。F12 表现为请求无状态码无响应头。

### 追加修复(浏览器直接拦直连: ERR_BLOCKED_BY_CLIENT)
现象: 用户浏览器控制台 `GET http://10.8.54.24:9000/...pdf?... net::ERR_BLOCKED_BY_CLIENT`(App.vue 探测 fetch 行)。这是**浏览器客户端层拦截**(内容拦截扩展 / Chrome 私有网络访问策略),非 CORS、非后端;该环境直连 MinIO 永不可用,只能同源降级。
- 根因 Bug: `AxiosInst.js` 响应拦截器对 Blob 响应**直接返回 Blob 本体**(`return success.data`,非 response 对象),降级代码却写 `const blob = res.data` → undefined → 永远落入"后端返回异常"分支 → 降级失败预览空白。修复为 `res instanceof Blob ? res : res?.data...`。
- 体验: 新增会话级 `directDisabled`,探测被拦一次后后续文件直接走同源,不再重复发被拦红字请求;降级失败时同步关闭 previewing 避免留空卡。
- 结论: 该网络环境直链预览无解(客户端拦截),同源 Blob 是唯一可用路径;普通浏览器(无拦截)下直链逻辑仍优先生效。

### 追加修复(下载加速器拦截: IDM)
现象: 用户浏览器装了 IDM 扩展, 点击预览后**弹出 IDM 下载框**, 控制台 `GET .../api/x/fileview/raw/... net::ERR_BLOCKED_BY_CLIENT` (App.vue:124 同源 fallback 路径) + `AxiosError: Network Error` (unhandled rejection)。
根因: `/raw` 之前返回 `Content-Type: application/pdf` + `Content-Disposition: inline; filename="xxx.pdf"`, IDM 默认文件类型白名单命中 PDF → 抓取响应并弹下载 → 浏览器原始 fetch 被 IDM 取消 → `ERR_BLOCKED_BY_CLIENT`。
修复 (CFileViewer.java): `/raw` 改为:
- `Content-Type: application/octet-stream` (不在 IDM 默认白名单)
- `Content-Disposition: inline; filename="preview.bin"` (.bin 也不在白名单, inline 仍生效)
Open File Viewer 路由不受影响: 前端把真实 fileName (`xxx.pdf`) 作为 prop 传入, viewer 按扩展名路由到 pdfPlugin; pdfjs 通过文件签名 `%PDF-` 识别 PDF, 不依赖 Content-Type。
用户侧如需彻底排除该问题, 也可在 IDM 设置中把 `localhost:4177` 加到「不从此站点自动下载」白名单; 但代码层已无 IDM 拦截风险。
